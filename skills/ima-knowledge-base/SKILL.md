# ima 知识库检索

用户的腾讯 ima 账号里有一批知识库（个人库 + 共享库）。本会话可能已经注入了知识库清单（来源标记 `dsh-ima-context`），清单里列出的库都可以直接检索。**用户的私有资料问题，答案在库里，不在你的预训练知识里。**

本插件对外只有 5 个只读工具，没有写入能力：不能创建、上传、修改任何文件或笔记。

## 何时使用

- 「我的资料里有没有提到 X」「找找跟 X 相关的文档」→ 直接全局搜，这是最常用的一步
- 「我那个 XX 文档写了什么」→ 先搜到文件，再读全文
- 「帮我整理一下 XX 项目的记录」→ 搜索多个关键词，把命中的文档逐个读
- 「我有哪些知识库」「XX 库里有什么」→ 列库或浏览目录
- 用户提到内部项目名、产品名、人名（你不认识的专有名词）→ 先搜库，再决定是否需要问用户

## 何时不用

- 公开知识、通用编程问题、与用户私有资料无关的闲聊 → 不要为了「多查一步」而搜库，白花 token
- 用户要新建、上传、修改笔记或文件 → 本插件只读，如实说明，不要承诺
- 订阅类知识库 ima 不开放读取：它们不会出现在清单里，也搜不到。用户问起时说明这一点，不要反复重试

## 工具选择顺序与判据

| 目标 | 工具 | 判据与注意 |
| --- | --- | --- |
| 不知道文件在哪，只记得内容大概 | `ima_search_files` | **默认第一步**。按正文内容搜，不传 `knowledge_base_id` 时全局搜所有库 |
| 只知道库名，或想确认有哪些库 | `ima_search_knowledge_bases` / `ima_list_knowledge_bases` | 按库名搜用前者；要全部库或按个人 / 共享过滤用后者 |
| 已知某个库，想看有哪些文件、进子文件夹 | `ima_list_kb_files` | `knowledge_base_id` 必填；`folder_id` 传空串或不传表示库根目录 |
| 已经拿到某条结果的 `media_id` | `ima_read_file` | `media_id` 必须来自前面工具的返回，不要自己拼 |

顺序原则：默认「先搜后读」；只有用户明确说「看看 XX 库里有什么」时才先列目录。不要反过来先猜 `media_id` 再读。

## 会话调用示例

- 用户说「我的资料里有没有关于降本方案的文档？」→ 用 `ima_search_files`，`query` 传「降本方案」；命中多条时列出标题、类型、所在库和命中片段。
- 用户说「XX 项目库里有啥？」→ 若不确定库名，先 `ima_search_knowledge_bases` 找库，再 `ima_list_kb_files` 浏览根目录。
- 用户说「把第 3 条读出来」→ 取上一条结果里的 `mediaId` 调 `ima_read_file`，读完再总结，引用原文。
- 用户说「我有哪些知识库？」→ 用 `ima_list_knowledge_bases`，按个人库 / 共享库分组列出名称和条目数。

## 引用规范

回答里提到库内资料时，写清楚来源，方便用户回查：

- 文件：「根据《文档标题》（知识库：库名）」
- 原文片段用引用块，别改写成自己的话再冒充原文
- 用户问「哪份文档提到过 X」时，列出标题 + 所在库 + 命中的那一段原文
- 多篇对比时，每段结论都标来源

## 失败与重试

- **一次没命中**：先换关键词（同义词、英文名、项目缩写、去掉长句里的修饰词），再指定库缩小或扩大范围；仍无结果时，说明搜了哪些库、没找到，请用户补关键词，不要立刻断言「库里没有」。
- **结果太多太杂**：加限定词（人名、日期、产品名），或先指定 `knowledge_base_id`。
- **读不到正文**：见下方「常见坑」里的二进制直链与截断。
- **`bound: false`**：账号未绑定，转告用户去侧边栏「知识库 ima」面板完成绑定，不要重试。
- **订阅知识库权限错误**：提示「订阅知识库内容暂不支持读取」时（错误码 220030），解释这是产品策略，引导去 ima 客户端查看，不要换关键词反复试。

## 常见坑

- **`media_id` 与文件名无关**：返回结果里的字段叫 `mediaId`，调工具时参数名是 `media_id`，别把两个名字搞混；它是搜索 / 目录返回的不透明 ID，原样传参，不要截断或猜测。
- **`folder_id` 必须来自列表返回**：形如 `folder_7451432378726676`；空串表示库根目录；把文件的 `media_id` 当 `folder_id` 传会失败。
- **二进制文件返回直链不是正文**：只有 Markdown、文本、笔记三类能直接读正文；网页、Word、PPT、Excel、图片、XMind、录音、视频、播客等返回 `binary: true`、直链 `url` 和一句 `message` 说明原因，不要假装读到了内容；告诉用户文件在哪，引导他在面板里预览或复制链接。
- **文本可能被截断**：正文超过约 512KB 时会截断（`truncated: true`），只能基于已有部分回答，并明确说明未读完整。
- **单页上限**：知识库列表一次最多 20 个库；目录一次最多 50 条，返回里的 `isEnd` 为 false 表示还没列完，当前工具不支持翻页，不要声称「这就是全部文件」，可进子文件夹或让用户用面板浏览；全局搜索每个库最多展示 5 条、总计最多 30 条，结果里带 `knowledgeBase` 库名，拿不准时换关键词再搜一轮。
- **订阅知识库不展示、搜不到**：它们被产品策略过滤掉了，不是你的关键词写错了；硬读这类条目会报 220030。
- **命中的片段只是片段**：`highlight` 是命中位置附近的一小段，回答前需要读全文核对，别把片段当全文结论。

## 与本插件其它入口的关系

- 侧边栏「知识库 ima」面板：用户手动浏览、预览文件、把内容发到对话
- `/ima <关键词>` 斜杠命令：用户手动搜库，结果直接显示在命令结果里（不进模型上下文）；不带关键词则列出全部知识库
- `ima` 伞形技能：先判断该不该用、该走哪个技能
- `ima-notes` 技能：专门处理笔记正文的阅读与整理
- 三者共用同一套凭证与工具，结果可以互相衔接
