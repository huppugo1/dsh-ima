# ima 笔记阅读与整理

本插件里的「笔记」，指的是用户 ima 知识库 / 个人库里的文档条目。插件没有独立的笔记接口，定位和读取都走同一套只读工具；读回来的是服务端展平的纯文本，文字内容在，但标题层级、表格、图片位置等结构会丢。整理时的第一原则是**忠于原文、按锚点重建结构，而不是凭想象补格式**。

## 何时使用

- 「帮我找一下上次和 XX 开会的记录」
- 「把这篇笔记整理成要点 / 摘要」
- 「这篇笔记里提到的待办有哪些」
- 「我记过的关于 XX 的笔记，找出来看看」
- 「这几篇笔记对比一下 / 按时间顺序串起来」

## 何时不用

- 找的是 PDF、Word、Excel、PPT 等普通文件 → 用 `ima-knowledge-base` 的方式检索和读取
- 只是想确认「库里有没有提到 X」→ 先用 `ima-knowledge-base` 搜到条目，再回到本技能整理
- 用户要新建、追加、修改、删除笔记 → 本插件只读，如实说明边界
- 公开知识、通用问题、闲聊 → 不用任何 ima 技能

## 会话示例与执行顺序

1. **「帮我找一下上次和 XX 开会的记录」**
   用 `ima_search_files` 搜会议、纪要、对方名称、日期等关键词（可先全局搜，再按库缩小）→ 从结果里挑最接近的条目（标题含会议 / 纪要，或命中片段是会议内容）→ 用 `ima_read_file` 读全文 → 按时间、议题、结论重排后回答，标清《标题》（知识库：库名）。
2. **「把这篇笔记整理成要点」**
   上下文里已有具体条目就直接读；只有模糊描述就先搜、把候选标题列给用户确认，别猜错笔记 → 读全文 → 输出结构化的要点（3 到 7 条），关键结论保留原文引用块。
3. **「这篇笔记里提到的待办有哪些」**
   读全文后只抽行动项：谁、做什么、什么时候。原文没写负责人或截止时间就标「原文未写」，不要脑补；拿不准归属的放「待确认」。
4. **「这几篇笔记对比一下」**
   逐个 `ima_read_file`，先给每篇一两句摘要并记住来源，再给对比结论；冲突的信息并列呈现并标注各自出处，不要合并成一个「事实」。
5. **「我记过关于 XX 的笔记」**
   搜索后列出标题、所在库、类型和命中片段；返回里没有时间字段时，只按标题和内容判断新旧，不要编造日期。

## 整理方法

- 服务端返回的是展平文本：先通读一遍，再按发言人、时间戳、小标题关键词（如「议题」「结论」「行动项」「待办」）重新分块。
- 保留原文关键句为引用块，不把自己的总结写进引号里冒充原文。
- 完全看不出结构时，直说「原文为展平文本」，按语义分段并保持原始顺序，不要虚构表格或标题层级。
- 待办只从原文明确写出的内容里抽；推断出来的内容单列为「可能的待办（待确认）」。
- 多篇笔记先各自摘要，再做合并或对比；时间线用原文里能确认的时间点。

## 引用规范

- 引用格式：《标题》（知识库：库名）
- 引用原文用引用块，并标明来自哪篇笔记
- 多篇对比时，每段结论后面都标来源，方便用户回查

## 与官方 ima-skills 的差异

- 官方 ima-skills 的 notes 模块有独立笔记接口：搜索笔记、列笔记本、读正文，还能新建笔记（`import_doc`）和追加内容（`append_doc`）。
- 本插件只读：只能通过知识库的搜索、目录、读取看到笔记内容；没有「笔记本」概念，不能新建、追加、修改、删除。
- 用户要求写入时，如实说明本插件只读：建议在 ima 客户端里编辑，或使用已安装的官方 ima-skills 的 notes 能力。
- 绝对不要先答应「我帮你记下来」，再实际什么都没写。

## 常见坑

- **结构丢失**：纯文本会丢掉 Markdown 层级、表格、图片和附件位置，不要声称「表格里写着…」或「图 3 显示…」。
- **笔记与普通文本文件混在一起**：结果里标题旁的类型可能显示「笔记」，也可能是 Markdown / 文本文件；按类型和内容判断，别只看标题。
- **正文截断**：超过约 512KB 会截断（`truncated: true`），只能基于前部回答，并说明后面没读到。
- **订阅知识库里的笔记读不到**：订阅库内容受产品策略保护，可能报「订阅知识库内容暂不支持读取」（错误码 220030），引导用户去 ima 客户端查看，不要重试。
- **`media_id` 必须来自搜索或目录返回**，不能手写或截断；同一篇笔记在不同库里可能重名，引用时带上库名。
- **`bound: false`**：账号未绑定，按 `ima` 伞形技能里的引导话术处理，不要反复调工具。

## 与其它技能的关系

- `ima` 伞形技能：先在模糊请求里做路由，判断该用本技能还是 `ima-knowledge-base`。
- `ima-knowledge-base`：负责文件 / 库层面的检索、目录浏览与普通文件读取；本技能负责笔记正文的阅读与整理。
- 侧边栏「知识库 ima」面板与 `/ima` 命令：用户手动浏览和搜库的入口，与本技能共用同一套凭证。
